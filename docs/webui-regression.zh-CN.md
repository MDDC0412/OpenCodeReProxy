# WebUI 浏览器回归

`npm run test:web` 使用 Playwright CLI 驱动真实 Chromium 浏览器，覆盖嵌入 Go 程序的 HTML、CSS、JavaScript 与管理接口。不会为生产前端引入框架。

## 运行

需要 Go、Node.js 22 或更新版本，以及 Playwright CLI 能启动的 Chrome 浏览器。先安装开发依赖；缺少 Chrome 时可使用 CLI 安装：

```bash
npm ci --ignore-scripts
npx playwright-cli install-browser chrome
npm run test:web
```

运行器会检查本机 19090、19091、19092 端口未被占用，再建立 `.local/browser/run-时间戳-PID/` 测试配置、日志和独立可执行文件。19090 是管理端，19091 是 API，19092 是本地模拟上游。测试配置只有演示凭据，不读写用户运行配置，不停止现有服务；端口已占用则直接报错。

每次使用新的浏览器会话，结束后关闭该会话及本次启动的网关和模拟上游。测试过程中会创建、重命名、启停和删除演示 API Key，并编辑、保存和恢复测试轮转配置。失败时保留本次独立配置与日志供排查。`.local/`、`.playwright-cli/`、`output/` 均被 Git 忽略。

浏览器脚本必须返回包含 `passed` 和 `browserErrors` 的最终结果；退出码为零但未到达结果（例如被原生确认框暂停）仍视为失败。删除操作在测试中替换 `window.confirm`，执行的是实际 DELETE 和后续鉴权验证。

## 覆盖范围

- 九页导航、独立请求台、六项统一状态检查、无请求中性状态、默认可见的用量和最近请求。
- 配置齐全但成功率偏低时，顶部、检查摘要、异常项数量一致；失败数量及处理入口明确，失败请求筛选可开启和取消。亮暗模式及 1440 / 1024 / 390 / 320 像素宽下，名称与状态点保持在各自边框内。
- 监控 HTTP 失败、目录过期、异常代理及恢复；模拟错误不能误提示刷新成功。
- 请求台模型搜索、键鼠选择、JSON 同步，以及经真实网关调用本地模拟上游。
- 真实 `/api/monitor`、`/api/debug/models`、`/api/model-quotas` 字段与页面对照；共享额度、无 Go Key 和历史额度标记。
- API Key 创建、复制 Key / 环境变量、复制失败退路、行内重命名、启停、删除；API 实际返回 200 / 401 验证立即生效。
- CC Switch 的 `big-pickle` 默认、Zen / Go 候选、三种客户端 endpoint、空目录手填、剪贴板拒绝退路、旧异步结果隔离和表格行高。
- 弹窗 Escape、焦点恢复、Tab / Shift+Tab、背景 inert、搜索列表不被滚动容器裁剪，鼠标选择不会误点遮罩；退出登录清空敏感复制缓冲、密码与自定义 Key 表单，迟到的复制失败不能重新展示密钥。
- 主题模式、预设色、颜色选择器、hex 输入、刷新保留、存储被拒绝时的页面内存状态；亮暗模式下黑 / 白 / 极浅黄 / 蓝 / 紫 / 青主题的按钮与选中浅底对比度。
- 长 Key 名、长模型名；1440、1024、390、320 像素宽下九页无文档横向溢出。
- 应用异常和 CSP 违规检查。测试显式模拟的 503 及初始未登录 401 不作为意外错误。

截图及最终报告保存到 `output/playwright/`：包括亮色总览、各宽度的暗色总览、导入弹窗和手机长名称场景。失败时另存 `failure.png`。宽表可以在自己的容器内滚动；无文档溢出不表示表格每列同时可见。

## 验收边界

模拟上游返回固定模型、额度和 Chat 响应，不证明真实 OpenCode 凭据、额度、网络或模型推理可用。正常启动仍可能刷新公共模型元数据；测试不向真实 OpenCode 上游发送推理或额度请求。

CC Switch 验证深链内容和系统交付前的界面行为，未验证操作系统注册协议、外部应用唤起或最终导入结果。浏览器为隔离的 CLI 会话，不能据此断言用户日常浏览器里曾出现的外部字体错误一定来自扩展。

主题初始化脚本位于 CSS 之前；保存偏好和无存储场景已覆盖，首次绘制的短暂闪烁仍需在用户的浏览器与加载条件下观察。

Go 的并发检测需要 C 编译器。本次 Windows 本机缺少 gcc，不宣称已运行 `go test -race`；仓库 CI 保留 Linux race 检查。

## 2026-10-10 本机验收记录

Windows 环境中运行 `npm run test:web` 到最终报告，14 组场景通过，`browserErrors` 为空。桌面亮暗总览、390 / 320 像素导入弹窗和长名称场景已经目视检查。手机最近请求和 Key 表格在自身容器内横向滚动，避免将模型、请求 ID 和状态压成逐字换行。

`go test -count=1 ./...`、`go vet ./...`、`npm run check:web`、`npm run format:check`、Go 格式检查和 `git diff --check` 通过，程序构建成功。代理头单测包含伪造前缀、多行 `X-Forwarded-For`、非法链和远程 `X-Forwarded-Proto`；URL 脱敏覆盖无 host、相对 authority、IPv6 及路径 / 查询。

另用真实 OpenCode 上游地址的独立匿名配置启动 9090 / 9091；管理登录和健康检查返回 200，模型目录来自 live 刷新，没有 Go 凭据，额度接口返回空账户。仅核实目录与管理功能，没有把该结果当作真实上游推理或 CC Switch 外部导入成功的证据。运行配置、日志、截图和最终 JSON 报告未提交到 Git。
